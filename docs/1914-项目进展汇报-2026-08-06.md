## 三、阶段2：本地完整对战 📋 设计完成，即将实现

**目标：** 两名玩家在同一台设备上完成一局完整的对战——抽牌、购买、部署、移动、攻击、回合交替、胜负判定。

### 3.1 阶段2 要实现什么

```
一局对战的完整流程：

  回合开始 → 自动抽牌 → 购买单位(花费G) → 部署单位(花费Z) → 移动/攻击(花费Z)
     ↑                                                              ↓
     └──────────────────── 切换玩家 ← 结束回合 ←────────────────────┘
                                        ↓
                                  检测胜利条件
```

### 3.2 核心设计

#### 三种资源

| 资源 | 用途 | 获取 | 累积/清空 |
|------|------|------|-----------|
| 经济 G | 购买单位卡 | 每回合 +150 | **累积** |
| 战争点 Z | 部署单位 | 每回合 = 当前回合数 | 回合结束**清空** |
| 指挥点 K | 移动/攻击 | 每回合 = 当前回合数 | 回合结束**清空** |

#### 战场布局

```
        列0   列1   列2   列3   列4
行0  [ P1   P1   P1   P1   P1 ]   ← P1 后方
行1  [ P1   P1   P1   P1   P1 ]   ← P1 前线
行2  [ 中立  中立  中立  中立  中立 ]  ← 争夺区
行3  [ P2   P2   P2   P2   P2 ]   ← P2 前线
行4  [ P2   P2   P2   P2   P2 ]   ← P2 后方
```

- **胜利条件：** 在对方全部 5 条阵线（每列至少一个己方单位）上都有单位 → 胜利

#### 阶段2 包含的卡牌

| 单位 | 攻击 | 防御 | 花费G | 花费Z | 词条 |
|------|------|------|-------|-------|------|
| 步兵 | 3 | 4 | 30 | 1 | — |
| 骑兵 | 4 | 2 | 40 | 2 | 冲锋 |
| 火炮 | 5 | 2 | 50 | 1 | 突击 |

#### 阶段2 包含的词条

| 词条 | 效果 |
|------|------|
| **突击** | 进入战场后本回合可立即行动 |
| **坚守** | 受到伤害时减免 1 点 |
| **冲锋** | 首次攻击时不受反击伤害 |
| **收缴** | 消灭敌方单位时获得 50% 生产花费（默认 25%） |

#### 攻击规则（核心）

- 攻击与反击同时结算：双方各造成对方攻击力数值的伤害
- 火炮不可被反击
- 突击/冲锋单位的首次攻击免反击

### 3.3 技术架构

```
                    ┌─────────────┐
                    │ TurnManager │  回合流转、资源刷新、胜负检测
                    └──────┬──────┘
                           │ 读写
                    ┌──────▼──────┐
                    │ BattleState │  唯一的真实数据源
                    └──────┬──────┘
                           │ 只读传入
                    ┌──────▼──────┐
                    │  GameLogic  │  纯函数引擎：输入状态+操作 → 输出新状态
                    └──────┬──────┘
                           │ 返回新状态
                    ┌──────▼──────┐
                    │ BattleState │  更新为新状态
                    └──────┬──────┘
                           │ 信号通知 UI 刷新
              ┌────────────┼────────────┐
              ▼            ▼            ▼
        Board          HandManager     UI层
        (棋盘渲染)     (手牌/资源)     (界面)
```

**设计亮点：**
- 游戏逻辑层与 UI 层完全分离——核心逻辑不依赖任何 Godot 节点
- 未来联网时，双方只需要同步玩家的操作指令，不需要传输游戏状态
- 纯函数模式保证同样的操作序列在两端产生完全一致的结果

- 敌方单位默认显示为**灰色方块**——你看不到它的类型、攻防、词条

- 离开视野 → 重新变灰
- 潜行单位未被发现时 → **完全不显示**

## 五、整体技术架构

### 5.1 卡牌流转（全阶段通用）

```
抽到单位卡 → 进入待购买区 → 花费G购买 → 进入手牌（上限7张）
  → 次回合花费Z部署 → 进入战场（后方/前线）
  → 次回合可移动/攻击（消耗Z）
```

- 先手第一回合不抽牌
- 初始从卡组抽出 3 张 + 首发牌恒定加入购买区
- 待购买区上限：铜卡不限、银卡 3 张、金卡 2 张

### 5.3 架构特点

1. **数据驱动：** 卡牌属性全部存在 JSON 文件里，加卡/改数值不需要改代码
2. **纯函数引擎：** 游戏规则逻辑不依赖 UI，保证每步操作的结果确定且可预测
3. **信号驱动 UI：** 游戏状态变化后发信号，UI 自动刷新，不直接读写游戏数据
4. **联网兼容：** 同一套游戏逻辑既用于本地对战，也用于未来的网络对战

## 八、非程序员如何参与卡牌数据编辑

**不需要安装 Godot 引擎！** 只需要：

1. 在项目 `data/cards/units/` 目录下找到对应的 JSON 文件
2. 用记事本（或任何文本编辑器）打开
3. 修改数值，保存
4. 告诉程序员"我改了 xxx 的数值"
5. 程序员提交到 Git

**示例 — 步兵卡 JSON（infantry_01.json）：**

```json
{
  "id": "infantry_01",           ← 唯一ID，不要改
  "name": "步兵",                 ← 显示名称
  "nation": "neutral",           ← 阵营（后续会改）
  "type": "unit",                ← 卡牌类型
  "unit_class": "infantry",      ← 单位类别
  "cost_g": 30,                  ← 购买花费G — 可以改！
  "cost_k": 1,                   ← 部署花费Z — 可以改！
  "attack": 3,                   ← 攻击力 — 可以改！
  "defense": 4,                  ← 防御力 — 可以改！
  "vision_range": "adjacent_4",  ← 视野范围
  "attack_range": "adjacent_4",  ← 攻击范围
  "abilities": [],               ← 词条列表 — 可以添加！
  "rarity": "common",            ← 稀有度：common/silver/gold
  "art": "",                     ← 卡面图片路径（美术交稿后填入）
  "flavor_text": "堑壕中的士兵。" ← 风味文字 — 可以写！
}
```

### 单位类型总览

| 单位 | 视野 | 射程 | 入场规则 | 移动规则 |
|------|------|------|----------|----------|
| **骑兵** | 周围四格 | 周围四格 | 可部署在任意友方阵线任意位置 | 移动或攻击共一次 |
| **步兵** | 周围四格 | 周围四格 | 友方后方；若占领前线可部署阵地 | 移动或攻击共一次 |

| **战斗机** | 前方3×2 | 本列+邻列 | 同步兵 | 移动和攻击各一次 |
| **轰炸机** | 前方3×2 | 本列+邻列 | 同步兵 | 移动和攻击各一次 |
| **火炮** | 前方3×3 | 全图 | 友方后方 | 移动或攻击共一次 |
| **工事** | 所在阵线 | 无 | 修筑在100%占领阵线 | 无法移动 |
