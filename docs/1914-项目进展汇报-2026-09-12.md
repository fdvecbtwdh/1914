## 一、阶段4 完成内容

### 1.1 三种对战模式

| 模式 | 状态 | 说明 |
|---|---|---|
| 本地同屏 | ✅ 已有 | 原流程不变，主菜单进入 |
| **局域网 P2P** | ✅ 本期新增 | ENet 直连（端口 24565），UDP 自动发现（端口 1914），免输 IP |
| 互联网 P2P | 🔶 协议就绪 | 双方连轻量服务器（WebSocket），服务器只按房间转发字节，零游戏逻辑 |

**玩家约定：** 创建房间的一方是 P1（先手），加入的一方是 P2。

### 1.2 同步方案（为什么流量极小）

利用阶段2 埋下的纯函数架构，两端只交换三类消息：

1. **开局包**（房主→客机）：随机种子 + 卡组 —— 双方各自洗出完全相同的牌堆
2. **指令字典**（双向）：和本地模式 `submit_action` 完全相同的字典，一条几十字节
3. **状态指纹**（每条指令附带）：两端各自算一遍指纹，不一致立即报错——防止"悄悄不同步"

一整局对战总流量 < 100 KB。这就是"服务器零压力"的底气：哪怕走中继，服务器也只是转发小包。

### 1.3 主菜单

运行游戏首先进入主菜单：**本地对战 / 创建局域网游戏 / 加入游戏（输 IP 或点"搜索局域网主机"自动发现）/ 退出**。

### 1.4 服务器侧待办（给后端同学）

`docs/server-relay-protocol.md` 已定稿中继协议，附了一份约 40 行的 Node.js 参考实现——按房间号转发的字节管道，不理解游戏内容，1核512MB 可承载数千房间。部署到现有服务器后，客户端 `relay_create/relay_join` 即可打通互联网对战。

## 二、验证情况（全部无头自动化，未依赖人工测试）

| 测试 | 内容 | 结果 |
|---|---|---|
| 既有 5 套回归 | 规则引擎/回合/UI，约 198 项断言 | ✅ 全绿 |
| **确定性回放**（新） | 同种子两次开局 + 13 步指令序列 → 两份状态指纹完全一致 | ✅ |
| **双进程真实对战**（新） | 两个 Godot 进程（房主+客机）经真实 ENet 回环：握手→开局→3 回合脚本代打（购买/部署/移动/攻击/结束回合）→ 全程指纹核对 | ✅ 双方 exit 0，最终指纹一致 |

双进程测试的命令（也可以用来快速开一局无界面联机）：

```bash
godot --headless --path . -- --net=host --auto        # 窗口1：建房 + 脚本代打
godot --headless --path . -- --net=join:127.0.0.1 --auto  # 窗口2：加入 + 脚本代打
```

去掉 `--auto` 即为真人联机流程。

## 三、已知边界（下阶段处理）

1. **互联网直连未打通**：走中继路线（协议已定），未做 NAT 打洞
2. **断线处理从简**：对手掉线会提示并结束连接，暂无重连/断线续玩
3. **回合等待提示较弱**：对方回合时输入会被忽略，界面暂无醒目的"等待对手"横幅
4. 一条无害的 ENet 日志（创建主机时的 bind 报错但连接正常）待跟进确认
